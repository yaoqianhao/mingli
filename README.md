# 命理推演器（mingli）

一套**规则可审计**的传统术数排盘 / 断卦程序。纯 Python 标准库，无第三方依赖，
天文历法自己算，不调用任何万年历接口。

它做的事情：把阴阳、五行、干支、八卦、节气、二十八宿这套符号系统，按古法规则
装进盘面，输出**每一步都能追溯到具体规则**的推演结果。

它不做的事情：不编断语、不承诺准确性、不替你做决定。

## 快速开始

```bash
cd source          # 下面所有命令都在 source/ 目录里执行

# 交互模式（推荐先用这个）
python3 -m mingli

# 八字排盘
python3 -m mingli bazi --date "1990-06-15 10:30" --lng 116.4 --gender m

# 六爻：手摇结果（六次「背」数，自初爻起）
python3 -m mingli liuyao --coins 1,2,3,1,0,2 --date "2026-11-27 15:30" --ask 工作

# 六爻：已知卦名装卦
python3 -m mingli liuyao --hexagram "天火同人" --moves 1,4 --day 戊午 --month 寅 --ask 财

# 梅花易数：报数 / 时间
python3 -m mingli meihua --nums 37,82
python3 -m mingli meihua --date "2026-11-27 15:30"

# 工具：节气表 / 农历换算
python3 -m mingli jieqi 2026
python3 -m mingli lunar --date "2026-11-27 15:30"

# 任意子命令加 --html 可导出网页版盘面
python3 -m mingli bazi --date "2024-03-05 09:30" --html output/pan.html
```

所有子命令都支持 `--lng`（经度，东经正）、`--tz`（时区）、`--day23`（以 23:00 换日）。

## 七个引擎

### 一、八字（子平术）

```
python3 -m mingli bazi --date "1990-06-15 10:30" --lng 116.4 --gender m
```

**排盘链路**：真太阳时校正 → 节气定位 → 年柱（立春分界）→ 月柱（交节分界，五虎遁）
→ 日柱（儒略日推算）→ 时柱（五鼠遁）。

**输出层次**：
| 层 | 内容 | 规则 |
|---|---|---|
| 干支 | 四柱 | 年以立春、月以十二节为界 |
| 十神 | 日主与其余七字的关系 | 生我者印、我生者食伤、克我者官杀、我克者财、同我者比劫；阴阳同为「偏」 |
| 藏干 | 地支内藏 1–3 个天干 | 本气 0.6 / 中气 0.3 / 余气 0.1 |
| 旺衰 | 五行加权计分 | 月令 ×3，其余地支 ×1.5，天干 ×1.0，日干自计 1.0 |
| 取用 | 身强喜克泄耗、身弱喜生扶 | 只给方向，不给具体用神结论 |
| 大运 | 每十年一换 | 阳男阴女顺、阴男阳女逆；出生日到节气的天数，三日折一年 |

**注意**：旺衰用的是「计分模型」，是给出一组可复核的数字，不等于传统命书
「得令、得地、得生、得助」的定性判断。两者要并看。

### 二、六爻（纳甲筮法）

```
python3 -m mingli liuyao --coins 1,2,3,1,0,2 --date "2026-11-27 15:30" --ask 财
```

**摇卦编码**：每次三枚铜钱，数「背」——
`0 背（三面）` 老阴动 ｜ `1 背` 少阳 ｜ `2 背` 少阴 ｜ `3 背` 老阳动

**装卦四步**（全部硬编码，可核对）：
1. **定卦宫**：用京房八宫生成法——本宫卦 → 依次变初至五爻 → 游魂 → 归魂
2. **纳甲**：乾内子寅辰／外午申戌，坤内未巳卯／外丑亥酉，震同乾，巽同坤，
   坎寅辰午／申戌子，离卯丑亥／酉未巳，艮辰午申／戌子寅，兑巳卯丑／亥酉未
3. **安世应**：八宫第 1–8 卦的世爻位置为 `6,1,2,3,4,5,4,3`，应爻恒隔三位
4. **配六亲**：以卦宫五行为「我」，生我父母、我生子孙、克我官鬼、我克妻财、同我兄弟
   再按日干配六神（甲乙青龙、丙丁朱雀、戊勾陈、己螣蛇、庚辛白虎、壬癸玄武）

**断卦初判**（`--ask` 指定用神：财=妻财、官=官鬼、父=父母、子=子孙、兄=兄弟）：
逐爻检查月建、日辰的生克冲合、旬空、动爻化变，输出机械结论。
程序不替你拍板，只把每一条依据摆出来。

### 三、梅花易数

```
python3 -m mingli meihua --nums 37,82
```

- **报数起卦**：第一数 ÷8 定上卦，第二数 ÷8 定下卦，两数之和 ÷6 定动爻（余 0 按 8 / 6 算）
- **时间起卦**：年支数 + 农历月 + 农历日 → 上卦；再加时支数 → 下卦；总合 → 动爻
- **体用**：动爻所在之卦为用（事），不动者为体（我）
- **互卦**：二三四爻为下互，三四五爻为上互（看过程）
- **变卦**：动爻反转（看结局）
- **断法**：用生体（吉）、体用比和（吉）、体克用（小吉）、体生用（凶）、用克体（凶）

### 四、奇门遁甲（时家·转盘）

```
python3 -m mingli qimen --date "2026-11-27 15:30" --lng 116.4
```

**必须先说明口径**——奇门流派分歧最大，同一个时辰不同派能排出不同的盘。本实现选的是：

> **时家 · 转盘 · 拆补定局 · 中五寄坤二**

**定局五步**：

1. **定阴阳遁**：冬至→芒种用阳遁，夏至→大雪用阴遁（冬至一阳生，夏至一阴生）
2. **定元**：从不晚于当日的最近一个**符头**（甲日或己日）看地支——
   `子午卯酉`＝上元，`寅申巳亥`＝中元，`辰戌丑未`＝下元
3. **查局数**：二十四节气 × 三元 → 1–9 局（如「冬至惊蛰一七四」＝上元一局、中元七局、下元四局）
4. **排地盘**：按 `戊己庚辛壬癸丁丙乙` 的顺序，阳遁顺布、阴遁逆布，从局数宫起戊
5. **定值符值使**：时柱旬首所遁之仪（甲子→戊、甲戌→己、甲申→庚、甲午→辛、甲辰→壬、甲寅→癸）
   在地盘之宫 → 该宫地盘星为**值符**、该宫地盘门为**值使**

**三层转盘**：
- **天盘九星**：值符星移到「时干在地盘之宫」，其余星跟随；天盘干随星走；**天禽固定随天芮，中宫之干一并寄坤二**
- **人盘八门**：值使门从原宫起，阳遁顺数、阴遁逆数，数满时支数落到新宫，其余门跟随
- **神盘八神**：值符神落值符星宫，阳遁顺排、阴遁逆排

**九宫格读法**：

```
│巽4宫·东南·木           │离9宫·南·火             │坤2宫·西南·土           │
│九天　天蓬              │九地　天心              │玄武　天任              │
│景门                    │死门                    │惊门                    │
│天己　地丙              │天癸　地庚              │天辛　地戊(丁)          │
│三奇                    │                        │三奇                    │
```

每格五行：`八神　九星` / `八门` / `天盘干　地盘干` / 格局标记。
坤二宫显示成 `地戊(丁)` 是**中宫之干寄坤二**，不是错字。

**排列序可切**（`qimen.order.*`）：`num`＝1→2→3→…→9（洛书数序），`bagua`＝1→8→3→4→9→2→7→6（后天八卦顺时针）。默认星用 `num`、门神用 `bagua`。
若你所习的流派与此不同，改这三个参数即可，不必改代码。

**本实现不做的**：置闰法（超神接气过九日置闰）、飞盘派、阴盘奇门。这些在交节前后几天会给出不同局数。

### 五、大六壬（四课三传）

```
python3 -m mingli liuren --date "2026-11-27 15:30" --lng 116.4
```

六壬不用"局"，用**月将加时**转出一张天地盘，再从四课里推出三传。

**起课五步**：

1. **月将**：太阳过宫，以中气换将——雨水后亥将登明、春分后戌将河魁、
   谷雨后酉将从魁、小满后申将传送、夏至后未将小吉、大暑后午将胜光、
   处暑后巳将太乙、秋分后辰将天罡、霜降后卯将太冲、小雪后寅将功曹、
   冬至后丑将大吉、大寒后子将神后
2. **天地盘**：月将加在占时的地盘位置上，顺布十二支。天盘支压在地盘支上，
   就是这一课"当下"的格局
3. **十干寄宫**：甲寅 乙辰 丙巳 丁未 戊巳 己未 庚申 辛戌 壬亥 癸丑
   （口诀：甲课寅兮乙课辰，丙戊课巳不须论，丁己课未庚申上，辛戌壬亥是其真，
   癸课原来丑宫坐，分明不用四正神）
4. **四课**：日干寄宫起一课，取其上神再作下起二课；日支起三课，上神再作下起四课
5. **三传**：初传＝发用，中传＝初传的上神，末传＝中传的上神

**发用取法**（九宗门，主干已实现）：

```
伏吟/返吟 → 贼克（元首·重审）→ 比用（知一）→ 涉害 → 遥克 → 昴星
```

- **贼**＝下克上，**克**＝上克下。先取贼，无贼取克
- 一克独发＝元首（上克下）或重审（下贼上）
- 多克取"与日干同性"者＝知一；仍不止则比涉害深浅
- 无克取上神与日干遥相克者＝遥克
- 再无法，阳日取酉上神、阴日取酉下神＝昴星

**十二天将**：`贵人 螣蛇 朱雀 六合 勾陈 青龙 天空 白虎 太常 玄武 太阴 天后`。
日干定贵人（甲戊庚牛羊、乙己鼠猴乡、丙丁猪鸡位、壬癸蛇兔藏、六辛逢马虎），
昼用阳贵、夜用阴贵；贵人临亥子丑寅卯辰顺行，临巳午未申酉戌逆行。

**盘面读法**：

```
四课（下为地盘/日干寄宫，上为天盘）
　一课          二课          三课          四课
上戌(太阴)      辰(勾陈)      亥(天后)      巳(青龙)
下辰            戌            巳            亥

三传
  初传　亥（水）　乘天后
  中传　巳（火）　乘青龙
  末传　亥（水）　乘天后
```

**已知边界**：别责、八专两门本程序只作标识与简化取传；涉害的"归途深浅"
按顺数经过之克数计，属通行简法。遇到这些课体时输出会标 `[简]`，
需以你所习的传本核对。

### 六、紫微斗数

```
python3 -m mingli ziwei --date "1990-06-15 10:30" --lng 116.4 --gender m
```

紫微用**农历**排盘，生年干支以**春节**为界（不是立春）——这点和八字不同。

**起盘五步**：

1. **命宫**：寅起正月顺数至生月，再自该宫起子时**逆**数至生时
   **身宫**：同上但**顺**数
2. **宫干**：五虎遁——甲己起丙寅、乙庚起戊寅、丙辛起庚寅、丁壬起壬寅、戊癸起甲寅
3. **五行局**：命宫干支的纳音 → 水二 / 木三 / 金四 / 土五 / 火六
4. **紫微**：日数加最小补数 c 使之为局数的倍数，商 q 自寅顺数；
   **c 为偶再顺行 c 格，c 为奇则逆退 c 格**（这半句是全套口诀最容易记反的地方）
5. **天府**：与紫微以寅申为轴，`天府 = 16 − 紫微`。寅申同宫，巳亥对宫

**十四主星**（紫微一定，其余十三颗随之锁定）：

- **紫微系逆行**：紫微 → 天机(−1) →〔空一〕→ 太阳(−3) → 武曲(−4) → 天同(−5) →〔空二〕→ 廉贞(−8)
- **天府系顺行**：天府 → 太阴(+1) → 贪狼(+2) → 巨门(+3) → 天相(+4) → 天梁(+5) → 七杀(+6) →〔空三〕→ 破军(+10)

**辅星**：左辅（辰起正月顺）、右弼（戌起正月逆）、文昌（戌起子时逆）、文曲（辰起子时顺）、
地劫地空（亥起子时顺逆）、天魁天钺（年干）、禄存（年干）与擎羊陀罗（禄存前后一位）、
火星铃星（年支三合＋时支）、天马（年支三合）。

**生年四化**：甲廉破武阳、乙机梁紫阴、丙同机昌廉、丁阴同机巨、戊贪阴阳机、
己武贪梁曲、庚阳武阴同、辛巨阳曲昌、壬梁紫辅武、癸破巨阴贪。

**大限**：五行局数即起运虚岁（火六局 6 岁起），阳男阴女顺行、阴男阳女逆行，每宫十年。

**盘面**（中间为基本信息，◆命宫 ◇身宫）：

```
│田宅　庚辰            │　紫　微　斗　数           │财帛　乙酉            │
│紫微 天相             │　庚午年　火六局           │（空宫）              │
│                      │　命宫丑　身宫亥           │                      │
│                      │　                        │文曲                  │
│地劫                  │　◆ 命宫　◇ 身宫          │擎羊                  │
│大限 36-45            │　                        │大限 86-95            │
```

**已知边界**：
- 闰月按「作本月」处理，部分流派以下半月按下月
- 只排十四主星与主要辅星，**不排杂曜**（红鸾天喜、天刑天姚等）
- **亮度（庙旺利陷）与飞星四化未做**——这两项各家差异大，留待按所习补充
- 命主、身主未排（中州派按命宫地支、其他派按年支，口径不一）

### 七、工具：农历与节气

- `lunar`：公历 ↔ 农历。用 Meeus 新月公式定朔，以「冬至所在月为十一月」、

- `jieqi`：任意年份二十四节气及交节时刻（含「节／气」标注）。

## 规则权重：把定性规则变成可调参数

### 为什么这么做

古籍只给定性规则——「用神旺相有生则成，休囚受克则败」。它没告诉你：
月破扣几分？动爻克用神和旬空哪个更致命？两现取哪个？

各家注本的分歧，很大程度上就是**权重分歧**。本程序把这些分歧显式化成参数，
你可以直接改数字看结论怎么动。

**必须先讲清楚**：默认权重是我设的启发式数值，不是古籍原数。
这个世界上不存在"正确的权重"。这套东西的价值不在于算得准，
而在于**你能看清结论是被哪几个因子推着走的**——以及改一个参数，结论会不会翻。

### 参数结构

```
liuyao.month.lin          3.0    用神临月建
liuyao.month.po          -3.0    月破
liuyao.day.lin            2.0    临日辰
liuyao.day.chong_shuai   -2.0    日破（衰而逢冲）
liuyao.kong              -2.0    旬空
liuyao.moving.ke_yong    -2.5    动爻克用神
liuyao.hua.huisheng       2.0    化回头生
liuyao.shi.yong_on_shi    1.5    用神临世
liuyao.thresholds.*        —     吉凶分界（daji/ji/ping_lo/xiong）

meihua.relation.*          —     体用五种关系各自的分值
meihua.stage.*             —     本卦/互卦/变卦 三段权重（0.4/0.3/0.3）
meihua.wangshuai.*         —     旺相休囚死 修正

bazi.weight.*              —     月支/他支/天干/日干 计分权重
bazi.cang.*                —     本气/中气/余气 分配
bazi.strength.*            —     身强/身弱 分界

qimen.order.*              —     star/gate/god 的排列序（num 或 bagua）
qimen.score.*              —     吉门/凶门/吉星/凶星/三奇/门迫 的分值
```

### 三种用法

**1. 套预设**

```bash
python3 -m mingli liuyao --hexagram "天火同人" --moves 1,4 --day 戊午 --month 寅 --ask 财 --preset classic
```

- `classic`：古法倾向——月建压日辰、动爻权重最大、月破重罚
- `strict`：保守——惩罚放大、吉的门槛抬高，宁可判「待定」
- `loose`：宽松——吉的门槛低，把卦当倾向提示而非裁决

**2. 逐项覆盖**

```bash
# 把月破和忌神的惩罚都调轻，看结论会变成什么
python3 -m mingli liuyao --hexagram "天火同人" --moves 1,4 --day 戊午 --month 寅 --ask 财 \
  --set "liuyao.month.po=-0.5" --set "liuyao.moving.ke_yong=-0.5"
```

实测同一卦：默认 `-7.0 → 凶`，改完两个参数后 `-2.5 → 不利`。**结论确实翻了。**

**3. 存成配置文件**

```bash
python3 -m mingli rules --save my.json          # 导出默认值
python3 -m mingli rules --set "bazi.weight.month_zhi=4" --save mine.json
python3 -m mingli bazi --date "1990-06-15 10:30" --rules-file mine.json
```

`python3 -m mingli rules` 可以随时打印全部当前参数。

### 图形化：拖滑杆看结论变色

```bash
python3 -m mingli slider --engine liuyao --hexagram "天火同人" --moves 1,4 \
  --day 戊午 --month 寅 --ask 财 --out output/slider.html
```

生成一个自包含的 HTML（无外部依赖，双击即开）。左边是盘面，右边是权重滑杆，
**拖动任一滑杆，总分与结论实时变色**——红→黄→绿，还带"距边界几分"的提示。

五个引擎都支持：`--engine liuyao | meihua | qimen | liuren | ziwei`。

**原理**（这也是它不会算错的原因）：

所有引擎的评分都能写成线性式
```
总分 = Σ (mul_i × w_i)
```
- `mul_i`：该因子触发了几次 / 占多少权重段——由盘面决定，**前端不可改**
- `w_i`：该因子的权重——**滑杆改的就是它**

所以浏览器只做一次加权求和，没有重写任何命理规则。Python 算出盘面和因子表，
JS 只负责乘加。界面上的数字与命令行完全一致。

页面上还有：
- **预设按钮**：古法 / 保守 / 宽松，一键换一整套权重
- **阈值滑杆**：调「吉凶分界」，等于调"你敢下判断的门槛"
- **敏感性提示**：自动标出当前影响最大的那个因子

### 评分怎么算

以六爻为例，程序对用神逐项打分并列出明细：

```
【用神：妻财】取第5爻 九五 壬申（金）妻财
  月破（月建冲之）                 -3.0  －████████
  日辰克之                         -1.5  －████
  动爻父母己卯克用神（忌神当权）   -2.5  －███████
  ──────────────────────────────────────────────────
  合计                             -7.0　→　凶
```

每一项都对应一条明确的古法规则，改权重就是在改"你认为这条规则有多重"。
梅花同理（本卦/互卦/变卦三段加权 + 体卦旺衰），奇门则是对八宫要素求和。

## 案例记录：先锁预测，后填结果

### 为什么需要它

命理最容易犯的错不是算错，是**事后归因**：事情发生了，回头找个卦来套，
怎么说都对。要检验这套系统，唯一干净的办法是**预注册**——
在结果出现之前，把判断写死。

```bash
# 1. 录入：程序自己算分给判词，立即写盘加哈希
python3 -m mingli log add --engine liuyao --coins 1,2,3,1,0,2 \
  --ask 财 --note "这笔款能不能收回"

已锁定预测 0001
  引擎 liuyao　分数 -7.0　判词「凶」
  摘要 c9df8953b3778110d1d4
  此条已不可修改。

# 2. 等事情发生
# 3. 回填
python3 -m mingli log resolve 0001 --result 0 --note "确实没收回"

# 随时查验
python3 -m mingli log verify      # 校验哈希链
python3 -m mingli log stats       # 命中率 + 校准曲线
python3 -m mingli log list --pending
```

### 防作弊：双段哈希链

每条记录含两个摘要：

```
pred_hash  = H(id, engine, input, score, grade, predicted_at, prev_hash)
final_hash = H(pred_hash, result, result_at)
```

- 改**预测** → pred_hash 变 → 与下一条的 prev_hash 断链
- 改**结果** → final_hash 变
- 删**中间记录** → 后继记录的前驱哈希对不上

三种篡改都能被抓到（都有单元测试）：

```
【篡改预测分数】 0001：预测摘要不符（内容被改过，或哈希链断裂）
【篡改已填结果】 0002：结果摘要不符（结果被改过）
【删除中间记录】 0004：预测摘要不符 + 前驱哈希不符
```

结果一旦填过就不允许覆盖——这一点是硬拦的，不是提示。

### 统计里的关键一栏：校准曲线

```
校准曲线（同一判词下的实际吉率，越单调越说明分数有意义）：
  判词        案例    实际吉率  图示
  平／待定    13      46%       █████████
  吉          13      92%       ██████████████████
  大吉        13      85%       █████████████████
  ⚠ 单调性被打破——某个「更凶」的判词，实际吉率反而更高。
```

单看"准确率"没意义（判凶的一多，全猜凶也能有高准确率）。
**看判词与实际结果的单调关系**才有意义：如果「大吉」的实际吉率低于「吉」，
说明这个分数刻度没有区分力，或者样本还不够。

工具还会盯「待决比例」——若长期只回填顺手的那部分，这个比例会露馅。

### 裁决：同一批案例上比较两套权重

这才是「谁的注本更权威」的真正裁判方式。

```bash
python3 -m mingli log compare --db cases.json --a default --b classic
```

规则集写法：`default` / `classic`·`strict`·`loose` / `@rules.json`。

```
  规则集                可判案例  命中率   95% 区间
  默认                  27        89%      [77%, 100%]
  文件 reversed.json    28        61%      [43%, 79%]

配对比较（18 条两套规则都能判的案例）：
  只有 A 对：4 条　只有 B 对：1 条　两边都对：12 条　两边都错：1 条
  McNemar 精确检验 p = 0.375　→　差异不显著
```

三件事值得注意：

1. **配对检验用的是 McNemar**，只统计两套规则判断不一致的那些案例。
   两套都对的、都错的，不提供信息。
2. **可判案例数会不同**——判「平／待定」的不计入命中率。所以命中率不能直接横向比，
   真正的比较看配对那一段。
3. **时间稳定性**：把案例按时间等分，看命中率是否漂移。若前半 90%、后半 45%，
   说明高分是被某一段的运气撑起来的。

工具末尾会固定打一条警告：**用同一批数据调参再比较，等于让考生自己出题**。
这不是免责声明，是使用前提。

### 边界

- 这是**本地自证，不是第三方公证**。能改这个文件的人可以重算整条哈希链。
  它的作用对象是「三个月后的你自己」，不是法庭。
- 舍掉的案例不会自动留痕。所以务实地讲：**录入时就该把犹豫的那几笔也记上**，
  否则统计出来的是"我挑过的样本"。
- `log demo` 可以生成一个演示库，里面的结果**是按默认权重模拟的，不是真实占验**，
  只用来跑通流程。

## 校准工具：用案例反推权重

### 这是什么

前面那些权重是我凭经验拍的。这个工具把它们变成**待估参数**：
你给一批已知结果的案例，它反推哪组权重最能解释这些案例——并且
**如实报告这个"最能"有多不可靠**。

```bash
# 先生成一批合成数据（演示用，不是真实记录）
python3 -m mingli calibrate --make-demo output/demo_cases.json --cases 60

# 跑校准
python3 -m mingli calibrate --data output/demo_cases.json
```

### 案例格式

```json
{
  "engine": "liuyao",
  "cases": [
    {"date": "2026-01-01 10:00", "coins": [1,2,3,1,0,2], "ask": "财", "result": 1},
    {"hexagram": "天火同人", "moves": [1,4], "day": "戊午", "month": "寅",
     "ask": "财", "result": 0}
  ]
}
```

`result`：1 = 吉 / 0 = 凶。引擎内其余参数与命令行一致。
五个引擎都支持（`liuyao / meihua / qimen / liuren / ziwei`）。

### 方法

```
score_i = Σ_j x_ij · w_j        x_ij = 第 i 案第 j 个因子被触发的次数/份额
P(吉) = sigmoid(score_i)         预测：score > 0 判吉
```

带 L2 正则的逻辑回归，用 IRLS（牛顿法）求解，正则项压住小样本下的过拟合。
再配 bootstrap 求每个权重的 95% 区间。

### 输出里必须看的四个数字

| 指标 | 含义 |
|---|---|
| **留一交叉验证** | 校准权重的真实表现。每次留出一个样本训练再预测它 |
| **默认权重成绩** | 同一批数据、不做任何拟合的成绩。校准必须赢过它才有意义 |
| **基线** | 全猜多数类的准确率。赢不过它等于瞎猜 |
| **样本/特征比** | < 5 时，拟合出的权重基本是噪声 |

### 一个真实跑出来的结果

用默认权重模拟 60 条六爻案例（加 15% 噪声翻转），再让工具反推权重：

```
案例：60 条（吉 34／凶 26）　因子：19 个
样本/特征比：3.2（偏低）

模型表现：
  训练准确率　　85%　（拟合出来的，虚高，别信）
  留一交叉验证　67% ± 12%　← 校准权重的真指标
  默认权重　　　85%　← 同一批数据、不做任何拟合的成绩
  基线（全猜多数类）57%
  AUC　　　　　 0.92

  → 校准比默认权重低 18%，超出抽样误差。
    这不是说默认值对，而是说：这批数据撑不起一次校准，动不如不动。
```

**这个结果比"校准成功"有用得多**。数据本来就是按默认权重生成的，
默认权重理应是上限（85%，正好卡在 15% 噪声天花板上）；
而校准在 60 条样本上把噪声当成了信号，交叉验证掉到 67%。

工具还标出了三个"符号与默认值相反"的权重（化回头生、用神发动、世克用神）——
它们只是在小样本里被个别案例带偏了。

**要真正校准，至少得补到 200 条以上真实案例**，而且案例本身要可信——
这是这套方法最难的环节，不是算法。

### 边界

- 这是**统计拟合**，不是传统术数。它不验证"命理是否有效"，
  只回答"在你给的这批数据里，哪些因子的方向站得住"
- `--emit` 导出的权重是配合「score > 0 判吉」的尺度，
  与原来的分档阈值不同尺，载入需同时调整 `*.thresholds`
- 案例的 `result` 若有系统偏差（比如只记得准的、忘了不准的），
  校准会把偏差学得比原来更牢

## 精度与边界（重要）

| 项目 | 精度 | 说明 |
|---|---|---|
| 日柱 | 精确 | 儒略日直算，与万年历一致 |
| 年柱 / 月柱 | 取决于节气时刻 | 见下 |
| 节气时刻 | **较官方历书普遍偏早 2–9 分钟** | 太阳视黄经用 Meeus 低精度级数，公式固有误差 0.01°（≈15 分钟） |
| 农历 | 日级准确 | 朔的时刻精度约数秒，闰月判定已验证 |
| 真太阳时 | ±1 分钟 | 经度差 + 均时差（NOAA 近似式） |

**实践建议**：
1. 若出生时刻距交节在 15 分钟内，程序会打 ⚠ 警告——此时请用《中国天文年历》复核，
   因为节气分界错一分钟，月柱就可能整个错掉。
2. 经度不填默认 120°E（东八区中央经线）。北京约 116.4，上海约 121.5，
   乌鲁木齐约 87.6——差 30 度就是两小时，直接决定时柱。

**这套系统的根本边界**：程序能保证「符号 → 符号」的推演符合古法规则，
但不能保证「符号 → 现实」的映射成立。规则内部自洽，不等于对世界有效。
把它当作一套结构化的思考框架，比当作预测机器可靠。

## 一处需要说明的分歧

网上流传的六爻案例常出现「摇卦记录」与「卦名」对不上的情况。本程序以**卦名为准**
（因为装卦规则绑定的是卦象），遇到冲突会按卦理自行推导变卦。
例如「天火同人，初爻与四爻动」，正确变卦是**风山渐**——初爻阳变阴、四爻阳变阴，
下卦离变艮、上卦乾变巽。若某处写「风火家人」，那是把动爻位置搞错了。
